# F-020 Settings page + API

Ledger row: [F-020](../../../../../docs/feature-ledger.md) (Summary table and the
`#### F-020 Settings page + API` section). Status: accepted.

## Sub-features

- `/settings` shows AI 偏好, 服务商, 外观, 数据, 导出与导入.
- Changing 每次检索的片段数 and pressing 保存偏好 survives a reload.
- 导出设置（不含密钥） downloads JSON with no API keys; 导入设置 reads one back.
- `GET /api/settings` never returns key values.
- The settings file is written `0600` after a save.
- Every write is conditional on the page's revision (`ETag` / `If-Match`): a stale tab gets
  409 and the page shows 「设置已在别处更改，请刷新页面后再试」 without overwriting.

## How to get to it (user POV)

Library top bar → Settings → the settings page. Change a value in AI 偏好 → 保存偏好 →
reload. For the conflict, open `/settings` in two tabs and save in both.

## Driving it with control.py and $B

```bash
python3 .claude/skills/verify-reader3/scripts/control.py up --corpus smoke
python3 .claude/skills/verify-reader3/scripts/control.py evidence start F-020
$B goto "$BASE_URL/"
$B click '[data-testid="lib-topbar-nav-settings"]'
$B wait '[data-testid="set-screen"]'
python3 .claude/skills/verify-reader3/scripts/control.py evidence add --browse-screenshot 01-settings
python3 .claude/skills/verify-reader3/scripts/control.py api GET /api/settings --expect 200
python3 .claude/skills/verify-reader3/scripts/control.py fs stat ai_settings.json
python3 .claude/skills/verify-reader3/scripts/control.py fs cat ai_settings.json
python3 .claude/skills/verify-reader3/scripts/control.py api PUT /api/settings --json @/abs/path/to/evidence/stale.json --if-match '"stale"'
python3 .claude/skills/verify-reader3/scripts/control.py lane F-020 --dry-run
```

Save in the UI first, then run `control.py fs stat ai_settings.json`: `data.mode` must be `0600`. The
`api PUT` line with a stale `--if-match` must come back 409; `stale.json` is a body you write
into the evidence folder (or the sandbox) first, and `@` needs its absolute path: a relative
path resolves from your working directory and is refused with `refused_path`.

## Gotchas

- The ledger Confirm says `ls -l config/ai_settings.json`. In the sandbox that is never the
  repo file: run `control.py fs stat ai_settings.json`, which stats the sandbox settings file
  (`READER3_AI_SETTINGS` points there), and check `data.mode` is `0600`. Never `ls`, `cat` or
  `stat` the repo settings file; the sandbox file is the only one in scope.
- Before the first save the sandbox settings file does not exist (`fs stat` gives
  `not_found`): the server runs on default settings with no keys. That is expected.
- Never type a real API key into the sandbox page. A dummy value is enough to prove that
  `GET /api/settings` hides it.
- 导出设置 downloads through the browser; gstack may not save the file anywhere you can read.
  Prove the no-key claim with `api GET /api/settings/export` instead and keep the envelope.
- 重建全部索引 and 导出书库 JSON are stubs (F-036, F-037): measure them with `ui inert`, not
  here.
