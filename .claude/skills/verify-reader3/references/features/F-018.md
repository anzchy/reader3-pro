# F-018 Annotations + notes

Ledger row: [F-018](../../../../../docs/feature-ledger.md) (Summary table and the
`#### F-018 Annotations + notes` section). Status: partial.

## Sub-features

- Selecting text opens the toolbar: color dots, Marker / Wavy / Underline, Add Note, Copy,
  Delete, Ask AI.
- Marker / Wavy / Underline save a highlight in the chosen color; the toolbar closes.
- Add Note (on a fresh selection) opens the editor ("Write your thoughts...") and Save stores a note.
- The rail's Notes button lists the notes (「共N条笔记」).
- Annotations survive a reload and are persisted in the book's `notes.json`.
- Routes: `GET|POST /api/notes/{book_id}/{chapter_index}`, `PUT|DELETE
  /api/notes/{book_id}/{chapter_index}/{note_id}`, `GET /api/notes/{book_id}`.

## How to get to it (user POV)

Library → book card → select a sentence with the mouse → the toolbar appears above it → pick
Marker (the toolbar closes). Select a different sentence → Add Note → type → Save. Rail Notes
icon → the notes panel.

## Driving it with control.py and $B

```bash
python3 .claude/skills/verify-reader3/scripts/control.py up --corpus smoke
python3 .claude/skills/verify-reader3/scripts/control.py doctor
python3 .claude/skills/verify-reader3/scripts/control.py evidence start F-018
$B click '[data-testid="lib-book-card"][data-book-id="smoke_data"]'
python3 .claude/skills/verify-reader3/scripts/control.py reader state --wait 15
python3 .claude/skills/verify-reader3/scripts/control.py reader select "Alpha prose."
python3 .claude/skills/verify-reader3/scripts/control.py evidence add --browse-screenshot 01-toolbar
python3 .claude/skills/verify-reader3/scripts/control.py ui inert --testid rd-anno-type-marker --expect active
$B goto http://127.0.0.1:PORT/read/smoke_data/1
python3 .claude/skills/verify-reader3/scripts/control.py reader state --wait 15
python3 .claude/skills/verify-reader3/scripts/control.py reader select "Beta prose."
$B click '[data-testid="rd-anno-note"]'
$B fill '[data-testid="rd-note-editor-input"]' 'verify note'
$B click '[data-testid="rd-note-editor-primary"]'
python3 .claude/skills/verify-reader3/scripts/control.py ui inert --testid rd-rail-notes --expect active
$B wait '[data-testid="rd-notes-panel"]'
python3 .claude/skills/verify-reader3/scripts/control.py evidence add --browse-screenshot 02-notes-panel
python3 .claude/skills/verify-reader3/scripts/control.py fs cat books/smoke_data/notes.json
python3 .claude/skills/verify-reader3/scripts/control.py api GET /api/notes/smoke_data/1 --expect 200
python3 .claude/skills/verify-reader3/scripts/control.py evidence result PASS --note "selection emulated via reader select; Marker one POST 201; note on a fresh selection"
```

`PORT` is `up`'s port. The smoke corpus has one sentence per section ("Alpha prose." in
section 0, "Beta prose." in section 1), so the fresh selection for Add Note lives in section 1.
Marker through `ui inert --expect active` proves the one `POST … 201`. The ledger's
`books/{book_id}_data/notes.json` read-back is the sandbox file, read with
`control.py fs cat books/smoke_data/notes.json`. To keep it, `evidence add` its absolute path under
`up`'s `books_dir`. Reload with `$B goto` on the current `$B url`, then `reader state --wait 15`
and re-read the notes panel (`annotations.marks` in `reader state` counts the rendered marks).

## Gotchas

- The toolbar closes after Marker (also Wavy and Underline, PR #28), so the ledger's Confirm
  asks for a fresh selection before Add Note. Reopening the toolbar by clicking the
  `mark.annotation` and then Add Note is 009 debt #70: it saved a `type: note` quoting only
  the first character (2/2, 2026-10-01) or was rejected by the `create-empty-quote` guard with
  no POST (2/2, 2026-10-03; `reader state` shows the op in `diag`). Do not count it against
  the row; if you reproduce it, mention it in the result note.
- With the notes panel open, `rd-rail-notes` is covered by the panel at 1280×720 (panel z 40
  over rail z 30): clicking it times out. Navigate or reload to close the panel.
- After `book add`, `[data-testid="lib-book-card"]` matches more than one card: keep the
  `[data-book-id="smoke_data"]` part.
- The progress pill is per section (`progress.sectionPercent`, 「当前阅读至 N%」), so it is
  no evidence of where the note sits; use `reader state` and the notes panel.
- `reader select` is the one allowed emulation (no mouse drag in browse). Label it in the
  result note. Everything after it must be real `$B click`s.
- Never read the repo `books/`; the only `notes.json` that counts is the sandbox one.
- CFI is always null (#6–#8) and `PUT` accepts only `note_text` (#29): do not count either as
  a new failure.
