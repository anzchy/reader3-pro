# F-013 AI Q&A + summary

Ledger row: [F-013](../../../../../docs/feature-ledger.md) (Summary table and the
`#### F-013 AI Q&A + summary` section). Status: accepted.

## Sub-features

- Streaming Q&A over SSE: `POST /api/ai/question/{book_uuid}`.
- Summaries: `POST /api/ai/summary/{book_uuid}`, from the Summary / Highlights / Background
  buttons.
- Token-budget routing chooses full-book, multi-chapter or RAG, with keyword fallback when the
  book has no index.
- Stop cuts a streaming answer off.

## How to get to it (user POV)

With a provider enabled in `/settings`: open a book → rail AI Assistant icon → type in "Ask
about this book... (Enter to send)" → Send. The answer streams in; Stop cuts it off. The
Summary / Highlights / Background buttons each produce a summary message.

`up --ai-stub` starts the offline stub (the e2e `OllamaStub`) and writes the sandbox
`ai_settings.json` with the `ollama` provider pointed at it, before the server starts. No
real provider, key or network is used. Check the stub answered with
`control.py ai ask "Alpha prose" --book smoke_data` before driving the UI: `results[].text`
holds the stub's answer and `stub_stats.request_count` the number of requests it saw.

## Gotchas

- The ledger says "with a provider enabled in `/settings`". In the sandbox that provider is
  the stub, never a real key: do not enter keys on the sandbox `/settings` page.
- `ai ask` needs the book's `book_uuid` from the sandbox `books/<id>/ai_meta.json` and never
  writes one; without it the command fails with `no_book_uuid` before any request. The server
  mints the file the first time it lists the library, so `api GET / --expect 200` (or opening
  the library in `$B`) is the step that creates it; check with `fs cat books/smoke_data/ai_meta.json`.
- `--gate` needs `up --ai-stub`, otherwise `no_stub`. Without the stub the sandbox settings
  file is absent, so `ai ask` names the default provider `ollama` and the server would try a
  local Ollama: always launch with `--ai-stub` for this row.
- Routing to RAG needs an index (`book index`, semantic extra and cached model). Without one
  the keyword fallback answers, and it matches the **whole question** as a substring of a
  chapter (case-insensitive): "What happens in chapter one?" gets HTTP 400 "not indexed" on
  the smoke book, "Alpha prose" gets an answer. Say which path you proved in the result note.
- Do not `book index` the book you will `ai ask` in the sandbox: the server runs offline and
  transformers 4.57.3 raises `OfflineModeIsEnabled` on the semantic path even with the model
  cached, so every `ai ask` against an indexed book is HTTP 500 (`ai_failed`, 2026-10-03). The
  RAG path can only be proven outside the offline sandbox today.
- The server serializes AI requests per `{book_uuid}:{provider}` (`ai/queue.py`): one request
  holds the queue from before retrieval until its stream ends. So `--concurrency 2` proves the
  two answers come back, not that they overlap, and `--concurrency 2 --gate
  release-after-first-delta` cannot pass against the real server: stream 2 waits behind the
  gated stream 1, never shows a first delta, and stream 1 times out cut short ("Alpha
  是第一章的第一个"). Run concurrency ungated.
- To catch Stop mid-stream, arm the stub's gate with a request that does **not** take the queue:
  `ai ask "What happens in chapter one?" --gate hold` arms the gate, gets the fast HTTP 400
  "not indexed" (keyword fallback misses) and returns without holding a slot. The UI question
  then streams its first deltas and stops before the last one (the stub holds up to 5 s), so
  `rd-ai-stop` is clicked mid-stream. Do **not** arm with a background `ai ask "Alpha prose"
  --gate hold &`: it holds the queue, the UI question waits behind it, and Stop then lands on
  a *queued* request, which hits the queue-wedge bug below.
- Queue-wedge bug (found 2026-10-04, not fixed): a client that disconnects while **queued**
  makes `_wait_turn` raise `asyncio.CancelledError`, which `except Exception` in
  `_PerKeyQueue.enter` does not catch, so the item is never removed; it later becomes head and
  wedges the queue. Every later question and summary for that book and provider gets 504 "AI
  request timed out" until the server restarts (`control.py down` then `up`). Stop on an
  *active* stream is fine; the follow-up `ai ask` above checks that.
- After Stop the reader panel replaces the partial answer with the raw browser error
  ("Error: BodyStreamBuffer was aborted" / "signal is aborted without reason"); the static
  reader JS has no AbortError handling. Record it as a cosmetic deviation, not a Stop failure.
- Summary / Highlights / Background always run retrieval first with a fixed long query that the
  keyword fallback never matches, so on an unindexed book they answer HTTP 400 "not indexed"
  whatever the routing mode (known limit #26). With the offline sandbox unable to index (see
  above), the summary buttons cannot produce a summary there: the verdict is DEVIATES, citing #26.
