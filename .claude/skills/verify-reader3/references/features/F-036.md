# F-036 Library JSON export

Ledger row: [F-036](../../../../../docs/feature-ledger.md) (Summary table and the
`#### F-036 Library JSON export` section). Contract: 018 WI-6, rulings W6-1 – W6-11 and D19 in
`docs/plans/20260816-tech-stack-migration/tasks/018-library-routes.md`.

## Sub-features

- `/settings` → 导出与导入 → 导出书库 JSON (`set-export-json`) sends exactly one
  `GET /api/library/export` (no `include`, W6-6), saves `reader3-library.json` and shows
  「书库已导出。」; a failure shows 「导出书库失败：…」 (W6-10).
- The body is `{"books": [...]}` in `GET /api/library` order (W6-8). Each readable book is the
  WI-4 entry (`book_id`, `title`, `authors`, `cover_url`, `book_uuid`) plus `annotations` (the
  `notes.json` list) and `component_errors` (always present, may be empty, W6-3). No chapter
  text, no `conversations` key unless asked.
- `?include=conversations` (case-insensitive) adds `conversations`; any other value, an empty
  value, a comma list or a repeat is 400 `include must be "conversations"` (W6-7).
- Per-component failure (D19): an unreadable `notes.json` gives `annotations: null` plus
  `{"component": "annotations"}` in that book's `component_errors`; other books and the
  response status (200) are unaffected.

## How to get to it (user POV)

Library top bar → Settings → 导出与导入 → 导出书库 JSON. The browser downloads
`reader3-library.json` and the line under the buttons reads 「书库已导出。」.

## Driving it with control.py and $B

```bash
python3 .claude/skills/verify-reader3/scripts/control.py up --corpus smoke
python3 .claude/skills/verify-reader3/scripts/control.py doctor
python3 .claude/skills/verify-reader3/scripts/control.py evidence start F-036
$B goto "$BASE_URL/"
$B wait '[data-testid="lib-main"]'
$B click '[data-testid="lib-topbar-nav-settings"]'
$B wait '[data-testid="set-screen"]'
python3 .claude/skills/verify-reader3/scripts/control.py ui inert --testid set-export-json --expect active --settle 1.5
$B js 'document.querySelector("#set-export-result").textContent'
python3 .claude/skills/verify-reader3/scripts/control.py evidence add --browse-screenshot 03-export-clicked
python3 .claude/skills/verify-reader3/scripts/control.py api GET /api/library/export --expect 200
python3 .claude/skills/verify-reader3/scripts/control.py api GET "/api/library/export?include=conversations" --expect 200
python3 .claude/skills/verify-reader3/scripts/control.py api GET "/api/library/export?include=bogus" --expect 400
python3 .claude/skills/verify-reader3/scripts/control.py reader select "Alpha prose."
python3 .claude/skills/verify-reader3/scripts/control.py fs cat books/smoke_data/notes.json
python3 .claude/skills/verify-reader3/scripts/control.py evidence result PASS --note "UI click = 1 GET 200; body via api"
```

The `ui inert` line is the UI proof: `requests` must be exactly one
`GET /api/library/export` with status 200 and `writes` empty. The body comes from the `api GET`
lines; label it as API in the result note. To prove annotations flow through, open the smoke
book by clicking its card, `reader select "Alpha prose."`, then real clicks on `rd-anno-note`,
fill `rd-note-editor-input`, click `rd-note-editor-primary`, and export again. For the D19
check, overwrite `<books_dir>/smoke_data/notes.json` (the sandbox path from `up`'s
`books_dir`, never a repo `books/`) with non-UTF-8 bytes and export again: 200,
`annotations: null` and `component_errors: [{"component": "annotations"}]` on that book only.

## Gotchas

- gstack `browse` cannot capture the download (the page saves a `Blob` through a temporary
  `<a download>`). Prove the click with `ui inert` plus the 「书库已导出。」 line, and the body
  with `api GET /api/library/export`; say which part was UI and which was API.
- The UI never sends `?include=conversations` (W6-6); that branch is API-only.
- `book_uuid` in the export is read without the lock and never minted (W6-1): on a book that no
  page has listed yet it can be `null` while `GET /api/library` (which mints) shows a uuid.
  Open the library first (`$B goto "$BASE_URL/"`) if you compare the two.
- A smoke-corpus book has no cover, so `cover_url` is `null`; that is not an error.
