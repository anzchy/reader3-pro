# F-011 Keyword search

Ledger row: [F-011](../../../../../docs/feature-ledger.md) (Summary table and the
`#### F-011 Keyword search` section). Status: accepted.

## Sub-features

- In-book search from the reader's rail Search drawer, Mode on keyword; clicking a result
  jumps to it and highlights it.
- Whole-library search from the library's Search tab ("Search across your library...").
- Case sensitivity, and diacritic normalization: `cafe` matches "café".
- Deep links `?q=&occurrence=`.
- Routes: `GET /api/search/{book_id}`, `GET /api/search/library`,
  `POST /api/highlight/{book_id}/{chapter_order}`.

## How to get to it (user POV)

Reader → rail Search icon → leave Mode on keyword → type a word → click a result. Library →
Search tab → type a word to search every book.

## Driving it with control.py and $B

```bash
python3 .claude/skills/verify-reader3/scripts/control.py up --corpus smoke --epub ./some.epub
python3 .claude/skills/verify-reader3/scripts/control.py evidence start F-011
python3 .claude/skills/verify-reader3/scripts/control.py api GET "/api/search/smoke_data?q=Alpha" --expect 200
python3 .claude/skills/verify-reader3/scripts/control.py api GET "/api/search/smoke_data?q=cafe" --expect 200
python3 .claude/skills/verify-reader3/scripts/control.py api GET "/api/search/library?q=Alpha" --expect 200
$B click '[data-testid="lib-book-card"][data-book-id="smoke_data"]'
python3 .claude/skills/verify-reader3/scripts/control.py reader state --wait 15
$B click '[data-testid="rd-rail-search"]'
$B fill '[data-testid="rd-search-input"]' 'Beta'
$B press Enter
$B wait '[data-testid="rd-search-results"]'
python3 .claude/skills/verify-reader3/scripts/control.py evidence add --browse-screenshot 01-results
python3 .claude/skills/verify-reader3/scripts/control.py lane F-011 --runner pytest
```

The ledger's `curl 'http://127.0.0.1:8123/api/search/{book_id}?q=cafe'` becomes
`control.py api GET "/api/search/smoke_data?q=cafe" --expect 200`: same request, sandbox
server, no proxy.

## Gotchas

- `smoke_data` contains no "café", so `?q=cafe` there proves only that the route answers. To
  prove the diacritic match, pass an EPUB that contains "café" with `--epub` and search that
  book's id.
- Quote the API path: `?` and `&` are shell characters.
- The library search deserializes every book (#35); with several real EPUBs it is slow, so
  give `api` a longer `--timeout` if needed.
- After clicking a result, check the jump with `reader state` (`section.index`) and a
  screenshot of the highlight; the result list alone is not the proof.
