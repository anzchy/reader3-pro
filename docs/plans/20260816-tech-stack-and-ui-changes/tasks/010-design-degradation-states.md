## 2. S1–S5 逐条

五条的触发、UI 规格、落点见设计规格 §6.4 的表——**本文不复述那张表**。这里只写那张表没说、而实施时必须先定的事。

### 2.0 先建 `DegradeBanner`（四条的共同基座）

一个组件，四条复用。必须一次定死的：

- **tone 取值**：`warn` / `danger` 两档。S1/S2/S4 用 warn，S3/S5 用 danger（规格 §6.4 设计要求 1）
- **可关闭性**：`dismissible` 布尔。S1–S4 为 true 且写 `sessionStorage`，S5 不走这个组件（它是对话框）
- **可访问性**：`role="status"` + `aria-live="polite"` 挂在组件上，**不复用 `LiveRegion`**——那个是 `sr-only` 播报器，两者职责不同，混用会得到一个既看得见又被朗读两遍的东西
- **主操作插槽**：S2 要「重建索引」、S3 要「展开清单」、S4 要「重试失败项」。三个形状不同，用 children 而不是 `primaryLabel` 字符串

**testid**：容器与主操作按钮各一个，且必须**按状态区分**（`rd-degrade-s1` 而不是共用一个 `degrade-banner`），否则 009 的 `acceptance-p3` 断言不出「出现的是 S1 不是 S3」。

> **色彩 token 的三处问题已在 007 修完，本轨直接用现成的。** 这里原先记着三条未决。实测之后结论与预期相反，一并修进了规格：
>
> - **名字**：§6.4 已改成 `--r3-warning` / `--r3-error`（对齐 §3.3）。这条也是 Codex 复审 #8。
> - **淡底**：§3.3 补齐了 `--r3-{success,warning,error,info}-subtle` 四个，取原型已有的 `--*-bg` 实测值。**不设 border token**——状态前景色直接当边框，压在自己的淡底上 4.5–5.3:1，已过 WCAG 1.4.11 的 3:1。
> - **真正不合格的是亮色，不是夜间。** 原先每色只有 500 一档：白底上 green 2.28 / amber **2.15** / red 3.76 / cyan 3.68，四个全挂；压在纸夜底上反而 4.86–8.51 全过。已换成 700（亮）/ 400（夜）两档，实测表在 §3.3 代码块下方。**"夜间态没人验过"这个直觉指错了方向**，亮色才是漏的那档。
>
> **本轨要接着用的一条硬约束**：四个 `-subtle` 压在页面底上只有 1.10–1.22:1（亮色）、1.15–1.32:1（夜间）。`DegradeBanner` **只染一层底色等于隐形**——必须同时有边框或图标，边框用状态前景色。

### 2.1 S1 标注 stale（阅读器）

- 文案必须明说「标注暂停套用，**未删除**」——这是规格 §6.4 已定的，照做。理由值得写进设计注释：用户看到高亮消失的第一反应是数据没了，而这条降级恰恰是为了**不删**才存在的
- 「查看原文摘录」入口：摘录数据就是 `Annotation` 的 `quote` / `prefix` / `suffix` 三个字段，它们与 CFI 无关，指纹变了照样读得出。设计上按什么形态展示（内联展开 / 侧栏 / 弹层）本轨拍板
- Notes 面板逐条标记：面板里每条笔记加一个 stale 角标，与横幅是同一状态的两种粒度

### 2.2 S2 索引 stale（书库 ＋ 搜索面板）

书卡第五态。`STATUS_META` 加一项，**两个坑**：

1. **testid 是拼出来的**——`data-testid={"status-" + props.status}`。**这条已经没有选择余地**：设计规格 §4 新增的第 5 条（007 落的）把「testid 必须是字符串字面量」写进了契约。改静态映射表，五个值各写一遍。原先列的第二条出路「给 lint 开例外」作废——例外一开，以后每个动态 testid 都有先例。
2. **取值没兜底；而且补两处兜底是错的解法。** `reader.jsx` 的搜索面板直接 `window.STATUS_META[indexStatus].label`，后端先于原型发出第五态就抛。`StatusPill` 里确实有 `|| STATUS_META.not_indexed`——**但那个兜底本身是个 bug**：把未知状态显示成「未索引」是在断言一个它不知道的事实，用户会去点「开始索引」。
   正解是**一个共用取值函数** `statusMeta(s)`，未知值返回中性的 `unknown` 描述（灰点、文案「状态未知」），两处都走它。两个独立的 `||` 迟早漂移，这是同一个 canonical-definition 原则在代码里的样子。
   加第五态的顺序：**先改 `STATUS_META`、再改任何发出方**——加法式枚举的标准做法是消费方先行。

搜索面板顶部的「索引已过期」提示条走 §2.0 的 `DegradeBanner`，不要复用现有的 `index-banner`（那个是常态展示，不是降级）。

### 2.3 S3 pickle 回退告警（全局 chrome）

- 唯一一条**全局**降级：书库与阅读器都要显示。设计上要定它挂在哪——原型的两个页面外壳没有共享的顶部条，本轨要么建一个，要么接受两处各挂一次
- 「点击展开未迁移书目清单」：清单可能很长（全库），要定折叠形态与上限
- tone 是 danger。它不是「有个东西过期了」，它是「你正在用一个已知不安全的反序列化路径」

### 2.4 S4 存储格式 / 迁移进度（书库）

- 书卡 `storage_format` 角标：与 S2 的 `StatusPill` 是**两个独立维度**（索引状态 × 存储格式），别塞进同一个 pill。一本书可以「已索引 ＋ 旧格式」
- 迁移中的进度与失败项：失败项要能**单独重试**，所以每项要有自己的 testid 与按钮，不能只给一个总的「重试」

### 2.5 S5 多标签页写冲突（阅读器）

**这是唯一一条会真正丢用户数据的降级，也是现有 `Modal` 承载不了的一条。**

`Modal` 有三条互不相干的关闭路径，全都绕过「必须做出选择」：

1. header 里写死的 `×` 按钮（testid `modal-close`）
2. `.overlay` 的 `onMouseDown` 背景点击关闭
3. `useFocusTrap(ref, true, onClose)` 的 Esc

加上它把 `role="dialog"` 和 `data-testid="modal"` 都**写死在组件里**——`role` 改不成 S5 要求的 `alertdialog`，testid 也没法与其它弹层区分。

**裁定：S5 不复用 `Modal`，新建 `ConflictDialog`。** 三条关闭路径一条都不给，`role="alertdialog"`，两个按钮（「保留我的」/「采用远端」）是仅有的出口。顺带把 `Modal` 的 `data-testid` 改成**必传 prop**——不是「可传、默认 `modal`」。留默认值等于把撞名坑原样保留，而这个坑不只 S5 会踩。

**三条落地细节：**

- **Esc 不用改 hook。** `useFocusTrap(ref, active, onClose)` 的 Esc 分支写的是 `event.stopPropagation()` 之后 `onClose && onClose()`。传 `undefined` 进去，Esc 被吞掉且什么都不做，正是要的行为。**不要为此改 hook**——那会波及所有弹层。
- **先裁 `<dialog>` 还是 `div`。** 设计规格 §5 写的是「保留 `<dialog>`（原生 a11y 好）」，而原型的 `Modal` 已经是 `div.overlay` ＋ `role="dialog"`。两边没收敛，本轨裁并回写 §5。这条差异对 S5 是实质性的：原生 `<dialog>` 的 Esc 关闭发生在浏览器层，只有监听 `cancel` 事件并 `preventDefault()` 才拦得住；`div` 版不接 Esc 就完事。**推荐 `div` 版**——`ConflictDialog` 的全部价值在于关不掉，而原生 `<dialog>` 最大的优势恰恰是它自带的那套关闭行为。为了一个要拆掉全部关闭路径的组件去用它，是在跟平台对着干。
- **不许出现死胡同。** 「关不掉」的前提是两个出口始终可用。远端数据取不到时**不能把两个按钮都禁掉**——降级成「保留我的」单一选项，那仍然是一次决策。一个既关不掉又点不动的对话框比静默丢写更糟。

> S5 的后端侧（notes 乐观并发、409）在 Phase 2a，与本轨无依赖：本轨只产出 UI 与文案。规格 §9 也是这么分的（S5 → Phase 2a）。

## 3. 合同 2 收口（剩余两项）

合流计划 §3 列的两项，实测后发现状态不一样：

| 项 | 规格侧 | 原型侧 | 本轨要做的 |
|---|---|---|---|
| 标注暗色变体 | **已完成**——§3.3 的 night 块已经取了 `--p-hl-*-dk` 四个显式值 | **未改**，仍是 `color-mix`（九处） | 只剩原型侧，裁定见下 |
| 原型单层 token 名映射到两层 | 规格已定两层 | 原型仍是 `--canvas` / `--surface` / `--text` / `--anno-*` / `--page-*` | **不在本轨**，落点是 4A.1（合流计划 §3 已这么写） |

**这项比合流计划记的复杂，但比「要不要再定四个值」简单——它是 alpha，不是颜色。**

原型里 `color-mix` 有**九处**（不是八处），三个百分比：`.anno-chip.is-*` 四条 35%、`.marker.is-*` 四条 45%、`.anno.is-note` 一条 18%。九条**全部是 `color-mix(in srgb, X N%, transparent)`**——在 sRGB 里与 `transparent` 混合就是纯 alpha，等价于 `rgb(X / .N)`。

这直接消掉了原先那个问题：**「chip 档取什么显式值」是个假问题**。chip 与 marker 不是两种颜色，是同一颜色的两个不透明度。§3.2 每色一个 `-dk` 值就够，不需要再定四个更淡的。

**裁定：颜色存 RGB 三元组，alpha 留在使用处。**

```css
--p-hl-yellow-rgb:251 191 36;
--p-hl-yellow:rgb(var(--p-hl-yellow-rgb));   /* 需要实色的地方照旧引这个 */

.anno-chip.is-yellow { background:rgb(var(--r3-hl-yellow-rgb) / .35); }
.marker.is-yellow    { background:rgb(var(--r3-hl-yellow-rgb) / .45); }
```

排掉的三种写法，理由都是硬的：

| 写法 | 为什么不用 |
|---|---|
| `color-mix()` | 就是要拿掉的东西（Safari 16.2+），合流计划 §3 的原始理由 |
| `rgb(from var(--x) r g b / .35)` | 相对颜色语法，Safari 16.4 / Chrome 119，**兼容性比 `color-mix` 还差** |
| 手写 8 位十六进制 `#fbbf2459` | 能用，但 4 色 × 2 档 × 2 主题 = 16 个手调值，改基色要同步改 16 处 |

三元组 ＋ 斜杠 alpha 的 `rgb()` 从 Safari 12.1 / Chrome 65 起支持，比 `color-mix` 宽得多，**零 fallback**。代价是同一概念存两个 token（三元组 ＋ 实色别名）——Tailwind 与 Bootstrap 5 都这么做，是成熟做法不是权宜。

**夜间必须保留 alpha，而且 alpha 保不住高亮的可读性——两件事都实测过。**

`-dk` 四色是**深色**，在纸夜底 `#10151f` 上做 45% 合成，走向与亮色相反：

| 色 | 45% 合成后 正文/块 | 100% 实色 正文/块 | 45% 块/纸底 | 100% 块/纸底 |
|---|---|---|---|---|
| yellow `#8a6d1f` | 6.63 | **3.02** ✗ | 1.70 | 3.73 |
| green `#2f6b3d` | 7.45 | **3.94** ✗ | 1.51 | 2.86 |
| pink `#7d3b3b` | 8.42 | 5.06 | 1.34 | 2.23 |
| blue `#2f5580` | 8.03 | 4.74 | 1.40 | 2.38 |

读法有两层。第一层：**alpha 不是能不能省的问题，是不能省**——把 `-dk` 当实色铺，yellow 与 green 的正文对比掉到 3.02 / 3.94，破 4.5:1。45% 那档反而把正文抬到 6.63–8.42。

第二层是个更硬的结论，**换什么颜色都躲不掉**：纸夜底 L=0.0075、正文 `#c2ccdb` L=0.5977，要块底对纸底 ≥3:1 得 L≥0.1224，要正文对块底 ≥4.5:1 得 L≤0.0939 —— **可行区间是空集**。夜间不存在任何一个底色能同时「看得出被标了」和「标了还读得清」。（正文得亮到 L≥0.7258、约 `#dedede` 窗口才打开，那是改阅读主题正文色，不在本轨。）

> 所以夜间的**底色只能当提示，不能当信号**，标注必须同时有一个非底色的可辨识手段（下划线 / 左侧竖条 / 波浪线）。这与 §2.0 状态横幅那条结论是同一个形状——淡底自己说不了话。亮色不受此限：yellow 45% 压白底，正文仍有 9.95。


> **D-5 的一条漏网之鱼。** `.anno.is-note` 用的是 `color-mix(… var(--blue-500) 18% …)`。D-5 之前 `--blue-500` 只是个普通蓝；改成品牌色之后，「笔记类标注」的底色变成了 18% 品牌蓝，会与选中态、focus ring 撞。本轨要么给笔记标注另取一色，要么明确接受这个关联并写进 §3.2。

## 4. loading 骨架屏

原型 README 自己记着：「每个面板需要 loading / error / empty 三态。原型只做了 empty 与 error，**loading 骨架屏未建**」。规格 §5 的组件清单也把 `Skeleton` 标为**不存在**，现状是 `-` 或 `Loading...` 文本。

- 建一个 `Skeleton` 组件，书库卡片与统计数字先用上（§5 点名的两处）
- **尊重 `prefers-reduced-motion`**（§8 要求 5）：骨架屏的微光动效在 reduced-motion 下必须静止，否则它是全站最大的一处持续动画
- 骨架屏**不需要 testid**——它是过渡态，E2E 断言它反而会引入时序 flaky。要断言的是它之后的内容

## 5. testid 不在本轨（一处记账已修正）

合流计划 §6「线 3 Track D」原先把「§4.1 的 testid 批量改名」列为本轨产出并注明「喂给 0.5」。**那是重复记账**：0.5 自己的验收就是「134 条违规 → 归零」，且顺序写死为「先改原型、再回贴模板」——改原型那一半就是 0.5 的前半程。两处都声称拥有同一件事，会得到一个假的依赖环（0.5 → Phase 0 完成 → Track D → 0.5）。
